# Email Draft

Voice: `standards/voice.md`. Tool rules: `standards/tools.md` (Microsoft 365).

1. Find the source email if referenced by description. Read the full thread.
2. Load the client's `client.md` (contacts, relationship tone) when the recipient is a client. Never pull from `internal.md` into the body.
3. Recipient unclear: ask. Recipient not in `team/roster.md` or client contacts: flag.
4. Draft 2 to 5 sentences unless the content needs more. Open with the point, end with a clear ask or next step. Leader tone: direct but fair.
5. Append the signature block from `standards/tools.md` (Microsoft 365) as the last element. Lint the body (the block is exempt from banned-phrase review). Show the draft in chat with the plain-text block.
6. Save as Outlook draft only when Matt asks (reply-draft for threads, new draft otherwise). HTML `<p>` paragraphs, ending with the HTML signature block from `standards/tools.md`. Never send.
7. Reply-all to a meeting or calendar event: there is no reply tool for events and the invite email is often not in the mailbox. Search the calendar by title and date, take the attendee list, drop Matt, and create a new draft to the rest (organizer on To; Matt may move them to Cc). Subject is the standard one for the content (recap subject for recaps), unless Matt asks for "RE: <event title>". Same signature and no-send rules. Flag attendees whose affiliation is unconfirmed.
8. Client-facing: verification checklist (recipients, names, any commitments or dates you inferred).
9. If the email records a decision or commitment, propose a context write-back.
